# Gatelet mail access

Bedrock starts [Gatelet](https://github.com/hannesill/gatelet) alongside Hermes. Its image is pinned in `compose.yaml`; changing that pin is an explicit deployment change, not an automatic update. Gatelet is **not** automatically configured with a mailbox or connected to Hermes: OAuth, the per-account policy, and a bearer key require manual setup. Only Gmail and Outlook Mail are supported upstream; an Infomaniak mailbox cannot be connected natively.

## First setup

1. Bootstrap Bedrock (`bash scripts/install.sh`) or reapply it (`just install`). Forward the admin dashboard over SSH: `ssh -L 4001:127.0.0.1:4001 user@server`, then open `http://localhost:4001`. Port 4001 is host-loopback only; MCP port 4000 is **not** published to the host.
2. Retrieve Gatelet's generated admin token **on the server as root** without copying it into this repository or an LLM chat: `docker compose exec -T gatelet node -e 'process.stdout.write(require("fs").readFileSync("/data/admin.token", "utf8"))'`. Save it in a private password manager. The token is also encryption key material for stored OAuth credentials; losing it makes the database unusable. **Bedrock no longer backs up Gatelet's SQLite database or this token.** Arrange your own recovery before relying on it.
3. In Gatelet, create an API key under **API Keys** and connect the desired Gmail or Outlook Mail account under **Connections**. OAuth requires your browser to reach the forwarded admin port. Granting Google Gmail requires `gmail.readonly`, `gmail.compose`, `gmail.modify`; Outlook Mail upstream requests `Mail.ReadWrite` **and `Mail.Send`** despite the policy below. **These provider-side permissions are broader than the Gatelet policy**: someone with the OAuth tokens or admin access can bypass the MCP restriction.
4. Open the connection's **Policy editor (YAML)**, replace the `account` placeholder in `services/gatelet/policies/gmail.yaml` or `services/gatelet/policies/outlook-mail.yaml`, paste the **complete** policy, validate and save it. Gatelet stores policies in its SQLite database, not in mounted YAML files; its default permits archive. Recheck the active policy after any reconnection, preset change or upgrade, *before* connecting Hermes. Keep `send`, `reply`, and `archive` tools disabled.
5. For Outlook, `move` initially accepts only `Inbox`. To allow another destination, inspect **list_folders** and add only a verified non-Archive folder ID to `move.constraints.value` (`must_be_one_of`). Do not replace the allowlist with a blacklist: Archive can be addressed by an opaque ID. **Gmail cannot simultaneously allow `move` and forbid archiving:** upstream `gmail_move` always removes `INBOX`. `gmail_label` can also remove `INBOX`; both are disabled in the Gmail policy. Enabling either relaxes the no-archive requirement.
6. Connect Hermes only after confirming the policy. In the Hermes container use `hermes mcp add gatelet --url http://gatelet:4000/mcp` and set the private bearer key in the MCP server's `Authorization` header through interactive configuration (not in the repository or command line). Alternatively configure `mcp_servers.gatelet` with `url`, `headers.Authorization`, and a defense-in-depth `tools.include` list (`gmail_search`, `gmail_read_message`, `gmail_create_draft`, `gmail_list_drafts`, `gmail_list_labels` for Gmail; `outlook_mail_search`, `outlook_mail_read_message`, `outlook_mail_create_draft`, `outlook_mail_list_drafts`, `outlook_mail_list_folders`, `outlook_mail_move` for Outlook). Use `hermes mcp test gatelet` to check discovery; verify no send/reply/archive tools are exposed, then reload MCP/restart the Hermes gateway. A Hermes tool allowlist supplements but does **not** replace Gatelet policy. Disconnect any pre-existing direct email MCP integration.

**Privacy:** The proxy can filter some password-reset/security messages, but mail read results still go to the configured Hermes model. Gatelet is not local-only LLM processing. An agent with Docker host/daemon access or the Gatelet admin token can bypass the separation; keep Docker credentials and host access away from the mail-reading agent.

## Operations

`just status`, `just gatelet-start`, `just gatelet-stop`, and `just gatelet-logs` operate the pinned service. `just stop` stops Hermes alone. There are no Bedrock backup, restore, scheduled update, monitor, or health-check commands for Gatelet. The admin dashboard only listens on host loopback; do not publish it on the internet. Rotate the API key after suspected exposure; changing the admin token without re-encrypting data loses access to saved OAuth credentials.
