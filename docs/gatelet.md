# Gatelet mail access

Bedrock starts [Gatelet](https://github.com/hannesill/gatelet) alongside Hermes. The image is pinned to `0.2.4` (release `v0.2.4`); upgrading requires reviewing the upstream release and changing `GATELET_IMAGE` in the Compose configuration. The service is **not** automatically configured with an account or connected to Hermes: OAuth, the per-account policy, and a bearer key require manual setup. Only Gmail and Outlook Mail are supported upstream; an Infomaniak mailbox cannot be connected natively.

## First setup

1. On the server, bootstrap Bedrock (`bash scripts/install.sh`), or reapply it (`just install`). Forward the admin dashboard over SSH from your own computer: `ssh -L 4001:127.0.0.1:4001 user@server`, then open `http://localhost:4001`. Port 4001 is host-loopback only; MCP port 4000 is **not** published to the host. `just gatelet-check` confirms that its container is running (Gatelet has no application-level Docker healthcheck).
2. Retrieve Gatelet's generated admin token **on the server as root**, without copying it into this repository or an LLM chat: `docker compose exec -T gatelet node -e 'process.stdout.write(require("fs").readFileSync("/data/admin.token", "utf8"))'`. Save it in a private password manager. The token is also the encryption key material for the stored OAuth credentials; losing it makes the database unusable.
3. In Gatelet, create an API key under **API Keys** and connect the desired Gmail or Outlook Mail account under **Connections**. OAuth requires your browser to reach the forwarded admin port. Granting Google Gmail requires `gmail.readonly`, `gmail.compose`, `gmail.modify`; Outlook Mail upstream requests `Mail.ReadWrite` **and `Mail.Send`** despite the policy below. **These provider-side permissions are broader than the Gatelet policy**: someone with the OAuth tokens or admin access can bypass the MCP restriction. Do not treat the policy as a provider-side revocation of Send.
4. Open the connection's **Policy editor (YAML)**, replace the `account` placeholder in `services/gatelet/policies/gmail.yaml` or `services/gatelet/policies/outlook-mail.yaml`, paste the **complete** policy, validate and save it. This step is required: Gatelet stores policies in its SQLite database, not in mounted YAML files; its default permits archive. Recheck the active policy after any reconnection, preset change or upgrade, *before* connecting Hermes. Keep the `send`, `reply`, and `archive` tools disabled.
5. For Outlook, `move` initially accepts only `Inbox`. To allow another destination, inspect **list_folders** and add *only a verified non-Archive folder ID* to `move.constraints.value` (`must_be_one_of`). Do not replace the allowlist with a blacklist: the Archive folder can be addressed by an opaque ID. **Gmail cannot simultaneously allow `move` and forbid archiving:** upstream `gmail_move` always removes `INBOX`. `gmail_label` can also remove `INBOX`; both are disabled in the Gmail policy. If you choose to enable either, you explicitly relax the no-archive requirement.
6. Connect Hermes only after confirming the policy. In the **Hermes container**, use `hermes mcp add gatelet --url http://gatelet:4000/mcp` and set the private bearer key in the MCP server's `Authorization: Bearer …` header via the interactive configuration/dashboard (not in the repo or the command line). Alternatively configure `mcp_servers.gatelet` in Hermes with `url`, `headers.Authorization`, and a defense-in-depth `tools.include` list (`gmail_search`, `gmail_read_message`, `gmail_create_draft`, `gmail_list_drafts`, `gmail_list_labels` for Gmail; `outlook_mail_search`, `outlook_mail_read_message`, `outlook_mail_create_draft`, `outlook_mail_list_drafts`, `outlook_mail_list_folders`, `outlook_mail_move` for Outlook). Use `hermes mcp test gatelet` to check discovery; verify no send/reply/archive tools are exposed, and only then reload MCP/restart the Hermes gateway. A Hermes tool allowlist supplements but does **not** replace the Gatelet policy. Stop/disconnect any pre-existing direct email MCP integration, otherwise Hermes may bypass Gatelet.

**Privacy:** The proxy can filter some password-reset/security messages, but mail read results still go to the configured Hermes model. Gatelet is not local-only LLM processing. An agent with Docker host/daemon access or with the Gatelet admin token can bypass the separation; keep Docker credentials and host access away from the mail-reading agent.

## Operations and recovery

- `just status`, `just gatelet-start`, `just gatelet-stop`, `just gatelet-logs`, `just gatelet-check` manage the pinned service. `just stop` stops Hermes alone; it does not stop Gatelet.
- `just backup` and the daily timer create **two** encrypted Drive archives: a Hermes archive and an online SQLite snapshot of Gatelet's DB plus its admin token. Both are read back and hash-verified before backup freshness is recorded or old archives are pruned. `just gatelet-backup-list` lists the Gatelet archives. Treat a decrypted Gatelet archive as a secret; it contains OAuth credentials and their decryption token together. Retention is 14 days; the Gatelet image is not upgraded by the weekly Hermes image update.
- To restore Gatelet, first restore the rclone recovery configuration (as described in the main README), then run `just gatelet-restore` or `just gatelet-restore gatelet-backup-YYYYMMDDTHHMMSSZ-PID.zip`. The script validates the snapshot, creates a **local pre-restore copy**, stops Gatelet, restores DB and token, and checks health. If restore fails, Gatelet stays stopped; inspect the local `pre-restore-gatelet-*.zip` snapshot under Hermes `backups/`. On a replacement server, `scripts/install.sh --restore` restores Hermes and the **latest** available Gatelet snapshot before its first new backup; if no Gatelet archive exists, it initializes a new empty Gatelet instance. To select a different Gatelet snapshot, run `just gatelet-restore <exact archive name>` afterward. Review Gatelet's policy and MCP key after recovery.
- The admin dashboard only listens on host loopback; do not publish it on the internet. Rotate the API key after suspected exposure; changing the admin token without re-encrypting data loses access to saved OAuth credentials.
